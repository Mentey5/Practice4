user command in docker file

Gemini said
The USER instruction in a Dockerfile sets the user name (or UID) and optionally the user group (or GID) to use when running the image and for any subsequent RUN, CMD, and ENTRYPOINT instructions.

By default, Docker containers run as root. In a production or DevOps environment, this is a significant security risk. Using the USER command is the primary way to follow the Principle of Least Privilege.

1. Basic Syntax
USER <user>[:<group>] or USER <UID>[:<GID>]

User Name: USER darupureddy

UID/GID: USER 1001:1001 (Often preferred in Kubernetes environments to ensure the ID matches the host's permissions).

2. Proper Implementation Flow
You cannot switch to a user that doesn't exist. Therefore, you must first create the user using a RUN command (which varies depending on the Linux family) before applying the USER instruction.

For Debian/Ubuntu (using useradd):
Dockerfile
FROM ubuntu:22.04

# Create a system user and group
RUN groupadd -r appgroup && useradd -r -g appgroup darupureddy

# Set ownership of the working directory
WORKDIR /app
RUN chown darupureddy:appgroup /app

# Switch to the non-root user
USER darupureddy

# Subsequent commands run as 'darupureddy'
CMD ["python3", "app.py"]
For Alpine Linux (using adduser):
Dockerfile
FROM alpine:latest

# Alpine uses slightly different flags
RUN addgroup -S appgroup && adduser -S darupureddy -G appgroup

USER darupureddy
3. Why Use the USER Instruction?
Security (Container Breakout)
If a vulnerability is found in your application and it is running as root, an attacker could potentially gain root access to the host machine. Running as a non-privileged user limits the damage an attacker can do.

Persistence and Permissions
When your application writes files (logs, uploads, etc.), those files will be owned by the user specified in the USER command. This is crucial when mounting volumes to ensure your host machine can read or write to those same files.

4. Common Pitfalls
Permissions for RUN commands: Once you switch to a non-root user, you cannot perform tasks that require root privileges, like apt-get install. Always finish your installations before switching the user.

WORKDIR Ownership: If you define a WORKDIR after switching to a non-root user, the directory will be created by Docker with root ownership. This often leads to "Permission Denied" errors when your app tries to write to its own folder.

Solution: Create the directory and change its ownership while still root, then switch users.

5. Overriding at Runtime
Even if a USER is defined in the Dockerfile, you can override it when starting the container using the --user flag:

docker run --user 1005 my-image

This is particularly useful if you need to run a quick administrative task inside a container that is normally locked down.

docker exec command

Gemini said
The docker exec command is used to run a new command inside a container that is already running.

It is the primary tool for debugging, inspecting logs in real-time, or performing manual database migrations without stopping your application.

1. Basic Syntax
docker exec [OPTIONS] CONTAINER COMMAND [ARG...]

The most common way to use it is with the -it flags:

-i (interactive): Keeps STDIN open even if not attached.

-t (tty): Allocates a pseudo-terminal (makes it look like a real shell).

Example: Opening a Shell
To "enter" a running container and look around:
docker exec -it <container_id_or_name> /bin/bash
(Note: If the container is Alpine-based, use sh instead of bash.)

2. Running One-Off Commands
You don't always need to enter a shell. You can execute a single command and get the output immediately.

Check environment variables:
docker exec <container_name> env

Check disk space inside the container:
docker exec <container_name> df -h

List running processes in the container:
docker exec <container_name> ps aux

3. Useful Options
Option	Description
-u / --user	Run the command as a specific user (e.g., root or appuser).
-w / --workdir	Specify the directory inside the container to run the command in.
-e / --env	Set temporary environment variables for just that execution.
-d / --detach	Run the command in the background (detached mode).
Example: Running as Root
If a container is running as a non-privileged user (as defined by the USER instruction in the Dockerfile), but you need to install a quick troubleshooting tool:
docker exec -u root -it <container_name> apt-get update

4. docker exec vs. docker run
This is a frequent point of confusion for beginners.

Feature	docker run	docker exec
Action	Creates and starts a new container.	Runs a command in an existing container.
State	Starts from the image state.	Interacts with the current live state (modified files, etc.).
Use Case	Deploying your application.	Debugging or maintenance.

5. Practical Example: Database Management
If you are running a MySQL or PostgreSQL container, you can use exec to run a backup or enter the database CLI directly from your host terminal:

docker exec -it my-postgres-db psql -U username -d database_name
